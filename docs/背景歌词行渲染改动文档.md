# 背景歌词行渲染改动文档（多行背景词支持）

面向目标：把本项目（TS）的多行背景歌词渲染与解析逻辑移植到其他使用同一套渲染/解析的项目（JS）。所有结论基于 @applemusic-like-lyrics/core 0.6.0 / react 0.6.0 / lyric 1.1.0

## 1 背景与目标

AMLL 原版渲染器一个主行只支持 1 条背景行：

- `convertExcessiveBackgroundLines`（amll-core.mjs 约 3292-3305）对连续 `isBG` 行从第 2 条起无条件翻成 `isBG=false`，无开关可用
- `buildLyricGroups`（约 7771-7784）+ `addBgLine`（约 6340-6362）是单槽：新的 BG 直接 `dispose` 旧的
- `optimizeLyricLines`（约 3454-3466）默认还会跑 `resetLineTimestamps` 等改写行时间

本项目目标（产品定案）：

1. 主行 A 绑定 B、C、D 多条背景行时，播到 A 先显示 B
2. 到了 C、D 的起始时间：当前正在播的背景行已播完则替换（blur dissolve 过渡），没播完则向下叠加
3. 叠加出来的行播完直接淡出，但该主行内最后播放的背景行不消失，随主行一起切行
4. C、D 仍属于 A 的内容，可点击行只有 A 一个，不新增可点行
5. 非绑定的背景行同时播放时至多 1 行
6. 不改 TTML 文件格式，只增量写两个已有命名空间的属性

## 2 数据链路总览

```text
编辑器内存 LyricLine[]（含 followMainTimeline / followMainLineId）
  -> 导出 amllToTTML（WASM）+ injectFollowTimelineMarkers（字符串后处理补属性）
  -> TTML 文件：<p> 上带 amll:followMainTimeline="true" amll:followMainLineId="<主行id>"
  -> 导入 ttmlToAmll（WASM）+ extractFollowTimelineMarkers（回读属性）
  -> useFileOpener normalizeAmllLyricResult（行 id 全部 uid() 重生成，旧 id 悬空）
  -> resolveFollowMainLine（id 精确匹配，悬空回退邻近主行并重绑 id）
  -> 预览 AMLLWrapper buildPreviewLines 分组
       主行 + 首条绑定 BG（B）  -> 递进 LyricPlayer 库内原生 bg 槽
       其余 C、D               -> 挂主行 queueRows，自绘浮层 bgLayer 渲染
       无 follow 的 solo BG     -> 时间重叠过滤后自绘渲染
```

## 4 预览层渲染规则实现

分组（buildBgGroups / buildPreviewLines）：

- `isBG && followMainTimeline` 的行归入绑定组；主行定位优先按 `followMainLineId` 精确匹配（mainOf），匹配不到回退「向前最近一条非 isBG 行」
- 绑定组内按 startTime 排序：rows[0]（B）走库原生 bg 槽，rows[1..]（C、D）挂 `main.queueRows`
- `playerLines` 只含主行 + 各组 rows[0]，C、D 从递库数组里摘出，绕开库的单槽降级
- `optimizeOptions` 传 `syncMainAndBackgroundLines: false`，防止库把主行与 B 的时间取并集改写

显隐（queueVisible，每 150ms 节流刷新 nowMs）：

- 基础窗口：`row.startTime <= now <= row.endTime` 且主行在播（mainOn）
- stack 模式：多行同时 active 则向下叠放（自绘层按 slot * 20px 排布）；末行在全部更早行播完后驻留，直到主行结束一起淡出
- replace 模式：前面还有行未播完时不显示新行（播完才替换）
- 非绑定 solo 行：时间重叠过滤（半开区间 `start < kept.end && end > kept.start`）保证同时至多 1 行，不重叠的全部显示
- 可点击：onLyricLineClick 里 isMainLine 守卫，非主行不 seek 也不动滚动

## 5 导出/导入约定

- 只写两个属性，均在根节点已声明的 `xmlns:amll="http://www.example.com/ns/amll"` 命名空间内，不改 TTML 结构
- `amll:followMainTimeline="true"`：旧字段，保持兼容
- `amll:followMainLineId="<主行id>"`：新字段，挂 `<p>` 上；`isBG && isDuet` 的行会随 `<span ttm:role="x-bg">` 输出，此时属性挂 span 上
- 注意：WASM 的 `backgroundVocal` 是单槽结构（types/ttml.ts:39），一个 `<p>` 至多嵌 1 个 `x-bg`；「多行背景」在文件层面表现为多个独立 `<p>` 主行 + 各自嵌 1 个 x-bg，绑定关系全靠 followMainLineId 串起来
- 参考对照：@applemusic-like-lyrics/ttml 的 `toTTMLResult`（amll-ttml.mjs 约 1261-1268）会把第 2 条起的 BG 提升为独立主行（promotedLine），与本项目的属性方案不同

## 6 已知限制

1. `followQueueMode` 目前只有类型声明与读取分支，无 UI 写入口、无导入导出序列化，replace 分支实际不可达，默认恒为 stack
2. 库内 optimize（resetLineTimestamps 等）会改写播放器看到的行时间，自绘浮层用的是原始克隆时间，行时间与词时间不贴齐时浮层与高亮可有毫秒级错位
3. WASM 二进制未改动，其 `amllToTtml` 单槽行为未验证（探针脚本思路：1 主 + 3 BG 跑 amllToTtml 再 ttmlToAmll，数 `<p>` 与 `x-bg` 个数）
4. 多行背景的「替换/叠加」只作用于预览层渲染，导出的 TTML 不含排队信息（除 followMainLineId 组关系外）

## 7 JS 项目移植清单

1. 纯逻辑两块（去 TypeScript 类型即为 JS）：
   - follow-main-timeline.ts 全文（约 130 行）：resolveFollowMainLine 的 id 匹配 + 邻近回退 + 重绑、reconcile 分级
   - AMLLWrapper 内 buildBgGroups / buildPreviewLines / queueVisible / soloRows / isMainLine（约 120 行）与 150ms 节流
2. CSS：index.module.css 的 bgStack/bgLayer/bgRow 系列整段拷走（CSS Modules 写法，JS 项目按需转全局 class）
3. 导出/导入：
   - 若同样用 wasm ttml-processor：把 scanFollowMarkerElements / inject / extract 三个函数与两个属性常量一并移植
   - 若用 @applemusic-like-lyrics/ttml 包：不要用它的 backgroundVocal 单槽承载多 BG，需自行在导出前后包一层属性注入/提取
4. 行 id 体系：只要导入时行 id 会重新生成，就必须实现「悬空 id 回退邻近主行并重绑」，否则重导入后整组绑定丢失、多行背景退化为单槽
5. 库调用点：`<LyricPlayer lyricLines={playerLines} optimizeOptions={{ syncMainAndBackgroundLines: false }} />`，其余 optimize 保持默认

## 8 验证方法

- 构造 1 主行 + 1 条绑定 B + 2 条 follow 的 C、D：播放验证先显 B、播完替换/未完叠加、末行随主行切
- 构造 2 条时间首尾相接的非绑定 BG：验证 solo 行都显示
- 导出再导入同一文件：验证 followMainLineId 悬空回退后绑定仍在
- `npm run build:tsc` 过类型检查（queueRows 字段已补）
